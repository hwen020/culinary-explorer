# Restaurant data policy

- **Demo** uses six fictional fixtures. The map positions are illustrative. Demo CSV and deterministic recommendations are available offline. Account reset affects that account’s own demo favorites, search history and conversations. Fixture rows, other accounts, authorized imports and live databases are retained.
- **Authorized imports** are accepted from verified administrators in live mode. Import only records you have the right to store, index and export. CSV requires `id,name,lat,lng`. Optional columns include `cuisine,rating,reviews,price,address,website,phone,hours,status`. Separate multi-value fields with `|`. Reuse the same IDs for updates. The original input fields remain in the database. The worker indexes name and cuisine.
- **Google Maps** supplies bounded live discovery. Full Places records are used to render current results. The database retains Place IDs and the time observed. Google records do not enter CSV export, Chroma, the LLM evidence set or persisted chat. Live map markers use Google Maps. Review the requirements for attribution, EEA billing and other service-specific terms before enabling public live use. [Google Places policies](https://developers.google.com/maps/documentation/places/web-service/policies)
